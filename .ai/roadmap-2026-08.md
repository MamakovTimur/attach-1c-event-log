# Roadmap: Присоединение журнала регистрации (август 2026)

Источник: независимое ревью от 28.08.2026. Текущая версия кода: **1.3.21**.

## Фаза 0 — Стабилизация (1–2 недели)

**Цель:** доверие и предсказуемость запуска.

- Синхронизировать версию README / ObjectModule / форма / GitHub releases.
- Сортировка `.lgp` по имени в таблице файлов.
- Предупреждение в dry-run о возможных дублях при «Объединить».
- CI: `test_lgp_*`, `check_duplicate_method_names.py`, syntaxcheck BSL.
- Чеклист post-merge в протоколе dry-run.

**KPI:** 0 регрессий «Ошибка формата потока» на эталонных fixtures.  
**Статус:** выполнено (1.3.19).

## Фаза 1 — UX администратора (2–4 недели)

**Цель:** снизить операционный риск.

- Кнопка «Восстановить из резервной копии».
- Wizard: копии → анализ → attach.
- Поиск в `srvinfo`: имя ИБ, дата каталога, размер ЖР.
- Экспорт протокола в файл.
- Прогресс-бар с ETA при перенумерации больших `.lgp`.

**KPI:** типовой merge «перенос кластера» < 15 минут с первого запуска.  
**Статус:** выполнено (1.3.20).

## Фаза 2 — Качество merge (1–2 месяца)

**Цель:** догнать лучшие части аналогов в нише lgf/lgp.

- Split/merge по дате внутри одного `.lgp`.
- Дедупликация (опционально) по fingerprint записи.
- Транзакции: не разрывать begin/commit при append.
- Read-only поддержка архивного формата (lgf+lgp в одном файле).
- Golden tests на 5–10 анонимизированных `.lgp`.

**KPI:** merge пересекающихся периодов без дублей; 0 битых транзакций на corpus.  
**Статус:** выполнено (1.3.21).

## Фаза 3 — Автоматизация (1 месяц)

**Цель:** сценарии без GUI.

- Запуск через `/C`: `Источник=...;Приемник=...;Режим=analyze|attach`.
- OneScript для регламентного merge.
- Exit codes: 0 OK, 1 валидация, 2 блокировка.

**KPI:** unattended attach в тестовом контуре.

## Фаза 4 — Расширение охвата (2–3 месяца, стратегически)

**Цель:** не потерять пользователей на `.lgd`.

- **Рекомендация:** путь B — документировать связку с `СкопироватьЖурналРегистрации` для SQLite.
- Путь A (мост lgf→lgd) — только при явном спросе.
