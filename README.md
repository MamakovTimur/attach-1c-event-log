# Присоединение журнала регистрации (старый формат)

Внешняя обработка для безопасного объединения текстовых журналов регистрации 1С:Предприятия (`1Cv8.lgf` + `*.lgp`) после переноса информационной базы или восстановления из резервной копии.

> **Не подходит** для нового формата SQLite (`.lgd`).

Совместимость исходного кода: **1С:Предприятие 8.3.10 и новее**. Готовая сборка проверена на **8.3.27.2325**.

## Зачем это нужно

Журнал копится в файлах, разбитых по периодам (день / неделя / месяц и т.д.). После переноса ИБ или восстановления из копии платформа часто создаёт **новый** каталог `1Cv8Log` (другой GUID/словарь). Старые `.lgp` нельзя просто скопировать: номера пользователей, событий и метаданных в записях ссылаются на словарь `1Cv8.lgf`, а в приёмнике нумерация другая.

Обработка:

1. Сопоставляет словари (пользователи и метаданные — по UUID, остальные объекты — по имени).
2. Дописывает в новый `1Cv8.lgf` отсутствующие объекты.
3. Копирует или дописывает выбранные `.lgp`, при необходимости перенумеровывая ссылки.
4. Удаляет индексы `*.lgx` (платформа построит их заново).

## Быстрая проверка (до отдачи пользователю)

```powershell
python tests/run_all.py
python tests/smoke_open_epf.py
```

`smoke_open_epf.py` реально запускает платформу (`1cv8 ENTERPRISE` + `/Execute` EPF на `_tmp_ib`) и **должен пройти** до того, как отдаём обработку пользователю: в логе не должно быть `Ошибка инициализации модуля` / `ОшибкаКомпиляцииВстроенногоЯзыка` / `Переменная не определена`.

## Бенчмарк Python-движка

Генератор создаёт одноразовые синтетические журналы и измеряет время, пропускную способность присоединения и пиковую резидентную память отдельного процесса. Для dry-run фиксируется только время: анализ намеренно не читает тела LGP.

```powershell
python tools/benchmark_event_log.py --sizes-mib 100 --scenario both --mode both --json-out benchmark.json
```

Для длительного прогона используйте `--sizes-mib 100,1024,10240`. Укажите `--work-dir`, только если тестовые журналы нужно сохранить; без него они автоматически удаляются. Бенчмарк проверяет Python-движок, а не производительность BSL внутри платформы 1С.

Ручное открытие: **Файл → Открыть** → `ПрисоединениеЖурналаРегистрации.epf` (безопасный режим **выключен**).

## Ускорение через Python (опционально)

Только в режиме **«На клиенте»**. Python **не обязателен**: без него обработка работает как раньше.

1. Установите [Python 3](https://www.python.org/downloads/) и отметьте **Add to PATH**.
2. Положите `tools/attach_event_log.py` **рядом с** `ПрисоединениеЖурналаРегистрации.epf`
   (или оставьте в `tools/` рядом с EPF при работе из репозитория).
3. После dry-run нажмите **Присоединить** — появится выбор:
   - **В этой обработке (1С)**
   - **Через Python на этом компьютере** (если Python и скрипт найдены)
4. Рекомендация зависит от объёма и перенумерации: большие журналы с перенумерацией — к Python;
   мелкое копирование без перенумерации — достаточно 1С.

Если Python не найден, обработка пишет понятное сообщение и предлагает обычный способ.

**MVP скрипта:** analyze; attach с copy / merge / replace и перенумерацией ссылок; удаление `*.lgx`.
**Пока не в Python:** дедупликация и разбивка по дням — с этими галками выбирайте присоединение в 1С.

Пример вручную:

```powershell
python tools/attach_event_log.py --mode analyze --src D:\jr\old --dst D:\jr\new
python tools/attach_event_log.py --mode attach --src D:\jr\old --dst D:\jr\new --conflict merge --out-log D:\jr\attach.log --report-json D:\jr\attach-report.json
```

Коды выхода: `0` OK, `1` ошибка данных/опций, `2` файлы заняты.

Перед первой записью Python-режим проверяет блокировки всех выбранных файлов и оценивает свободное место с учётом временного файла, перенумерации, объединения и уже опубликованных периодов. При недостатке места словарь `1Cv8.lgf` остаётся неизменным.

Каждый временный LGP проверяется по версии и GUID до публикации. Параметр `--report-json` дополнительно сохраняет размеры и SHA-256 результатов; точное число записей указывается для файлов, прошедших перенумерацию. В быстром побайтовом режиме записи повторно не подсчитываются.

## Сборка EPF из исходников

Если нужна пересборка в конфигураторе:

1. **Файл → Новый → Внешняя обработка**, имя `ПрисоединениеЖурналаРегистрации`, сохранить как `.epf`.
2. В дереве метаданных обработки: контекстное меню корня → **Загрузить из файлов**.
3. Указать каталог, в котором лежит `ПрисоединениеЖурналаРегистрации.xml`.
4. Сохранить EPF. Безопасный режим — **выключен**.

## Как пользоваться

Работать лучше **с копиями**, а не с живым `srvinfo`: ragent держит файлы ЖР открытыми.

1. Скопируйте старый `1Cv8Log` (источник) в доступную папку, например `D:\jr\old`.
2. Скопируйте текущий `1Cv8Log` (приёмник) в `D:\jr\new`.
3. Откройте обработку в режиме 1С:Предприятие (толстый или тонкий клиент с расширением работы с файлами).
4. Укажите каталоги вручную или через **Найти старый/текущий ЖР…** (поиск `1Cv8Log` в `srvinfo`/`reg_XXXX` по `1CV8Clst.lst` и фильтру имени ИБ; в списке — **имя ИБ, дата каталога, размер ЖР**).
   - Если клиент на Windows, а файлы ЖР только на Linux-сервере — выберите **На сервере** и вводите пути **как на сервере** (например `/home/usr1cv8/.1cv8/1C/1cv8/srvinfo/reg_1541/<UUID>/1Cv8Log`).
5. Можно идти по **Мастеру** в блоке **Действия** (шаги 1→2→3: копии → анализ → присоединение) кнопками **Далее / Назад** — кнопки анализа и присоединения там же. Краткое описание опций — вкладка **Справка**.

Форма сгруппирована: **Каталоги** (пути, поиск в srvinfo, режим выполнения) → **Резервная копия** → **Параметры склейки** → **Действия** → таблица файлов → вкладки Протокол / Отладка / Справка.
6. **Проанализировать (dry-run)** — быстрый план без записи: словари lgf, карта перенумерации, список файлов/объёмы/действие конфликта, проверка **только заголовков** `.lgp` (версия + GUID), блокировки. Тела `.lgp` в анализе не читаются. Дедупликация и разбивка по дням только оцениваются («будет при Присоединить»).
7. Снимите пометки с лишних файлов или нажмите **Выбрать файлы…**.
8. **Присоединить** — выбор способа (на клиенте): в обработке 1С или через Python; при необходимости резервная копия, проверка блокировок, затем запись. При перенумерации больших `.lgp` в строке состояния — счётчик записей и оценка оставшегося времени.
9. При ошибке после записи: **Восстановить из резервной копии…** — выбор каталога `*.bak_…` (в каталоге бэкапа или рядом с приёмником) и возврат `1Cv8.lgf` / `*.lgp`.
10. **Сохранить протокол…** — выгрузка текста протокола в `.log` / `.txt`.
11. Остановите рабочий процесс / кластер при необходимости, подмените боевой `1Cv8Log` содержимым `D:\jr\new`, запустите снова.
12. Откройте журнал регистрации и проверьте старый период.

Для файловой ИБ каталог приёмника подставляется сам (`КаталогИБ\1Cv8Log`). Сеансы лучше закрыть.

### Опции

| Опция | По умолчанию | Смысл |
| --- | --- | --- |
| **Режим выполнения** | На клиенте | переключатель **На клиенте** / **На сервере** (блок «Каталоги») — где читать и писать файлы ЖР |
| **Каталог резервной копии** | пусто | куда писать `*.bak_…`; пусто = рядом с приёмником (родитель `1Cv8Log`) |
| **Резервная копия изменяемых файлов** | да | перед записью копирует `1Cv8.lgf` и отмеченные `.lgp`; восстановление — **Восстановить из резервной копии…** |
| **Проверка целостности** | да | в анализе — только заголовок `.lgp` (версия + GUID); тела файлов не читаются |
| **Дедупликация записей** | нет | при «Объединить» пропускать записи с тем же отпечатком (дата + ключевые поля), что уже есть в приёмнике; **только при Присоединить** (в dry-run — оценка) |
| **Разбивать источник по дням** | нет | разложить записи `.lgp` источника по файлам `YYYYMMDD000000.lgp`; незакрытые транзакции не режутся по границе суток; **только при Присоединить** (в dry-run — оценка) |
| **Если файл периода уже есть** | Объединить | см. таблицу ниже |
| **Мастер** | шаг 1 | подсказки и **Далее/Назад**: копии → анализ → присоединение |
| **Справка** | вкладка | описание опций, когда включать и влияние на время/диск |
| **Сохранить протокол** | — | выгрузка протокола в `.txt` / `.log` |

### Если файл периода уже есть в приёмнике

| Режим | Поведение |
| --- | --- |
| **Объединить** | дописать старые записи в существующий файл (типичный день/неделя переноса) |
| **Пропустить** | оставить файл приёмника |
| **Заменить** | перезаписать файлом из источника |

## Где лежат файлы кластера

```
C:\Program Files\1cv8\srvinfo\reg_<порт>\<UUID информационной базы>\1Cv8Log\
```

UUID после переноса или восстановления из копии часто **другой**. Искать по дате папки или по имени ИБ в консоли кластера.

## Ограничения

- Только старый текстовый формат (`1CV8LOG` в начале файла).
- Большие `.lgp` при перенумерации обрабатываются потоково, но это может занять время (на шаге **Присоединить**).
- Обработка может работать с файлами **на клиенте** или **на сервере** (переключатель «Режим выполнения»). Для серверного режима пути указываются в нотации ОС сервера приложений; локальные `C:\Users\`, OneDrive, Desktop в режиме «На сервере» — ошибка/ожидание сети (обработка предупредит).
- Не открывайте журнал регистрации в конфигураторе, пока идёт запись в те же файлы.
- При объединении без дедупликации возможны повторы записей; дедуп/split на больших ЖР дороги — включайте осознанно.

## Требования

- Платформа 1С:Предприятие 8.3 (управляемые формы, клиентские файловые операции).
- Доступ к каталогам `1Cv8Log` источника и приёмника (лучше копии).
