# Присоединение журнала регистрации (старый формат)

Внешняя обработка 1С:Предприятие 8.3 для склейки текстового журнала регистрации (`1Cv8.lgf` + `*.lgp`) после переноса информационной базы в другой кластер.

> **Не подходит** для нового формата SQLite (`.lgd`).

> Разработка решения ведётся с помощью AI.

## Зачем это нужно

В кластере 1 журнал копился в файлах, разбитых по периодам (день / неделя / месяц и т.д.). Базу перенесли в кластер 2 — платформа создала **новый** каталог `1Cv8Log`. Старые `.lgp` нельзя просто скопировать: номера пользователей, событий и метаданных в записях ссылаются на словарь `1Cv8.lgf`, а в новом журнале нумерация другая.

Обработка:

1. Сопоставляет словари (пользователи и метаданные — по UUID, остальные объекты — по имени).
2. Дописывает в новый `1Cv8.lgf` отсутствующие объекты.
3. Копирует или дописывает выбранные `.lgp`, при необходимости перенумеровывая ссылки.
4. Удаляет индексы `*.lgx` (платформа построит их заново).

## Сборка EPF из исходников

Если нужна пересборка в конфигураторе:

1. **Файл → Новый → Внешняя обработка**, имя `ПрисоединениеЖурналаРегистрации`, сохранить как `.epf`.
2. В дереве метаданных обработки: контекстное меню корня → **Загрузить из файлов**.
3. Указать каталог, в котором лежит `ПрисоединениеЖурналаРегистрации.xml`.
4. Сохранить EPF. Безопасный режим — **выключен**.

## Как пользоваться

Работать лучше **с копиями**, а не с живым `srvinfo`: ragent держит файлы ЖР открытыми.

1. Скопируйте старый `1Cv8Log` (кластер 1) в доступную папку, например `D:\jr\old`.
2. Скопируйте текущий `1Cv8Log` (кластер 2) в `D:\jr\new`.
3. Откройте обработку в режиме 1С:Предприятие (толстый или тонкий клиент с расширением работы с файлами).
4. Укажите каталоги вручную или через **Найти старый/текущий ЖР…** (поиск `1Cv8Log` в `srvinfo`/`reg_XXXX` по `1CV8Clst.lst` и фильтру имени ИБ; в списке — **имя ИБ, дата каталога, размер ЖР**).
   - Если клиент на Windows, а файлы ЖР только на Linux-сервере — включите **На сервере 1С** и вводите пути **как на сервере** (например `/home/usr1cv8/.1cv8/1C/1cv8/srvinfo/reg_1541/<UUID>/1Cv8Log`).
5. Можно идти по **Мастеру** (шаги 1→2→3: копии → анализ → присоединение) кнопками **Далее / Назад** — существующие кнопки анализа и присоединения тоже работают.
6. **Проанализировать (dry-run)** — план без записи: карта перенумерации, объёмы, понятные предупреждения (идентификатор журнала / риск «чужого» заголовка), проверка начала файлов периодов, блокировки.
7. Снимите пометки с лишних файлов или нажмите **Выбрать файлы…**.
8. **Присоединить** — при необходимости резервная копия изменяемых файлов, проверка блокировок, затем запись. При перенумерации больших `.lgp` в строке состояния — счётчик записей и оценка оставшегося времени.
9. При ошибке после записи: **Восстановить из резервной копии…** — выбор каталога `*.bak_…` рядом с приёмником и возврат `1Cv8.lgf` / `*.lgp`.
10. **Сохранить протокол…** — выгрузка текста протокола в `.log` / `.txt`.
11. Остановите кластер 2, подмените боевой `1Cv8Log` содержимым `D:\jr\new`, запустите кластер.
12. Откройте журнал регистрации и проверьте старый период.

Для файловой ИБ каталог приёмника подставляется сам (`КаталогИБ\1Cv8Log`). Сеансы лучше закрыть.

### Опции

| Опция | По умолчанию | Смысл |
| --- | --- | --- |
| **На сервере 1С** | нет | читать/писать файлы на сервере приложений (клиент Windows + ЖР на Linux) |
| **Резервная копия изменяемых файлов** | да | перед записью копирует `1Cv8.lgf` и отмеченные `.lgp` рядом (`*.bak_…`); восстановление — кнопка **Восстановить из резервной копии…** |
| **Проверка целостности** | да | сверяет заголовок периода со словарём; незакрытая скобка считается ошибкой только в конце файла (обрыв проверки на ~2 МБ — не «битый файл») |
| **Дедупликация записей** | нет | при «Объединить» пропускать записи с тем же отпечатком (дата + ключевые поля), что уже есть в приёмнике |
| **Разбивать источник по дням** | нет | разложить записи `.lgp` источника по файлам `YYYYMMDD000000.lgp`; незакрытые транзакции не режутся по границе суток |
| **Если файл периода уже есть** | Объединить | см. таблицу ниже |
| **Мастер** | шаг 1 | подсказки и **Далее/Назад**: копии → анализ → присоединение |
| **Сохранить протокол** | — | выгрузка протокола в `.txt` / `.log` |

### Если файл периода уже есть в новом ЖР

| Режим | Поведение |
| --- | --- |
| **Объединить** | дописать старые записи в существующий файл (типичный день/неделя переноса) |
| **Пропустить** | оставить файл кластера 2 |
| **Заменить** | перезаписать файлом из кластера 1 |

## Где лежат файлы кластера

```
C:\Program Files\1cv8\srvinfo\reg_<порт>\<UUID информационной базы>\1Cv8Log\
```

UUID после переноса в новый кластер **другой**. Искать по дате папки или по имени ИБ в консоли кластера.

## Ограничения

- Только старый текстовый формат (`1CV8LOG` в начале файла). Архив «lgf+lgp в одном файле» в dry-run определяется и предупреждается; запись такого архива не поддерживается.
- Большие `.lgp` при перенумерации обрабатываются потоково, но это может занять время.
- Обработка может работать с файлами **на клиенте** или **на сервере 1С** (флаг «На сервере 1С»). Для серверного режима пути указываются в нотации ОС сервера приложений.
- Не открывайте журнал регистрации в конфигураторе, пока идёт запись в те же файлы.
- При объединении без дедупликации возможны повторы записей; dry-run предупреждает о незакрытых транзакциях на границе файлов.

## Требования

- Платформа 1С:Предприятие 8.3 (управляемые формы, клиентские файловые операции).
- Доступ к каталогам `1Cv8Log` старого и нового кластера (лучше копии).
