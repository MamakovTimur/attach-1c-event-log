# BSL внешней обработки ЖР

Цель: обработка, которую админ открывает файлом. Нет общих модулей конфигурации. Не подтягивать `ОбщегоНазначения.*` и паттерны документов БП.

Сначала прочитай существующий код в том же регионе модуля — повторяй его приёмы.

## Клиент / сервер

- Имена `Процедура`/`Функция` **уникальны во всём модуле формы**, включая разные директивы. Дубль `&НаКлиенте` + `&НаСервере` — форма не открывается (hotfix 1.3.1).
- Файловые хелперы: `&НаКлиентеНаСервереБезКонтекста` — один код для клиента и флага «На сервере 1С».
- Оркестрация с реквизитами формы: клиент зовёт сервер с **другим** именем (`*НаСервереКонтекста`).
- `&НаСервереБезКонтекста` — только если контекст формы не нужен.
- Клиентский UI: `ТекущаяДата()`, не `ТекущаяДатаСеанса()`.
- Платформа 8.3.10+: диалоги через `ОписаниеОповещения`. Не добавлять `Асинх`/`Ждать`.
- Новый обработчик события бесполезен без записи в `Form.xml` (`<Events>` / событие элемента).

## Массивы и циклы

`Массив` индексируется с **0**. `Количество()` — длина, `ВГраница()` — последний индекс.

```bsl
// Верно
Для Индекс = 0 По Токены.ВГраница() Цикл
    Элемент = Токены[Индекс];
КонецЦикла;

// Ошибка (пропуск [0] и выход за границу)
Для Индекс = 1 По Токены.Количество() Цикл
```

Поля записи `.lgp` в формате ЖР часто **1-based** (номер поля в скобочной записи) — не путать с индексом массива токенов.

## Формат ЖР (не SQLite)

- Старый текст: словарь `1Cv8.lgf` + периоды `*.lgp`. Не писать логику `.lgd`.
- Пользователи и метаданные в словаре сопоставлять по UUID, остальное — по имени.
- При простом копировании `.lgp` с чужим GUID — переписать заголовок на GUID/версию приёмника.
- Незакрытая скобка на лимите выборки ~2 МБ — не «файл повреждён»; ошибка целостности — только если обрыв в конце файла.
- После склейки удалять `*.lgx`.
- Большие `.lgp` — потоково, не целиком в строку.

## Стиль

- Регионы русского БСП-шаблона, как уже в модуле (`ОбработчикиСобытийФормы`, `ОбработчикиКомандФормы`, `СлужебныеПроцедурыИФункции` и внутренние `#Область`).
- Не плодить пустые обязательные «все 5 регионов», если таблицы на форме нет — не создавать `ОбработчикиСобытийЭлементовТаблицыФормы…`.
- Комментарии — зачем, не что. Экспорт `СведенияОВнешнейОбработке` — с описанием возврата.
- Сообщения пользователю — понятный язык админа, без кухни разработки.
- Версия в `СведенияОВнешнейОбработке` и в README держать согласованно, если меняется поведение.
