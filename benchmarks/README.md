# Бенчмарки Python-движка

Бенчмарк создаёт синтетический журнал старого формата и запускает реальный `tools/attach_event_log.py` в отдельном процессе. Время генерации входных данных в результат не входит.

Измеряются:

- время анализа или присоединения;
- пропускная способность присоединения;
- пиковая резидентная память дочернего процесса.

Для dry-run пропускная способность не рассчитывается: анализ намеренно читает только заголовки LGP.

## Контрольные команды

Быстрый прогон:

```powershell
python tools/benchmark_event_log.py --sizes-mib 100 --scenario both --mode both --json-out benchmarks/baseline-100mib.json
```

Длительный прогон перед оптимизацией или релизом:

```powershell
python tools/benchmark_event_log.py --sizes-mib 100,1024,10240 --scenario both --mode both --json-out benchmarks/baseline-large.json
```

Большие прогоны требуют соответствующего свободного места. Без `--work-dir` временные журналы удаляются автоматически.

Результаты зависят от диска и файлового кэша, поэтому сравнивать версии следует на одном компьютере с одинаковыми параметрами.

## Зафиксированные результаты

- `baseline-v1.3.38-100mib.json` — исходное состояние релиза 1.3.38.
- `optimized-direct-spans-100mib.json` — перенумерация прямой заменой полей без удаления и повторной вставки переносов строк.
- `optimized-fused-parser-100mib.json` — границы полей определяются тем же проходом, который выделяет записи из потока.
- `verified-header-100mib.json` — тот же оптимизированный путь с проверкой версии и GUID перед атомарной публикацией.

На контрольном компьютере тяжёлый сценарий 100 МиБ ускорился с 34,24 до 10,92 секунды, а пиковая память осталась на уровне 26 МиБ.

Контроль линейности на 1 ГиБ: 107,57 секунды, 9,5 МиБ/с и 26,4 МиБ пиковой памяти. Рост времени пропорционален объёму, существенный рост памяти не обнаружен.

Проверка заголовка временного результата не добавила измеримого замедления: контрольные 100 МиБ обработаны за 10,48 секунды.
